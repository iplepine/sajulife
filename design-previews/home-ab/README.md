# 홈 디자인 A/B 세트

2026-11-15 KST. 대표 요청: “타입 a/b처럼 ab 테스트 하듯이 현재 버전과 다른 버전으로 한 벌 더 디자인해서 만들어줘.”

여기서 A는 직전 대화에서 만든 캐릭터 홈 시안을 보관한 버전이다. 실제 운영 중 `/dashboard` 원본과는 구분한다. B는 같은 상품과 캐릭터를 사용하면서 정보 위계와 구성을 달리한 대안이다. 로그인 전 흰 바탕·검정 궁서체 화면은 두 안 공통으로 유지한다.

## 비교하기

- [A/B 비교](index.html): 모바일 나란히 / PC A / PC B, 진행 상태 선택.
- [A 단독](a.html): 캐릭터 중심. 두 해설자를 먼저 만나고 주 CTA로 이어진다.
- [B 단독](b.html): 시작 우선. 주 CTA를 먼저 제시하고 두 관점이 하나의 풀이로 이어지는 해설 노트를 보여준다.
- 상태 예시: `?state=start`, `?state=tci`, `?state=done`, `?state=error`.

문구·가격·상품 범위·주 CTA 목적지·세 단계·하단 5탭·PC 3메뉴·보조 서비스는 맞췄다. A/B의 실험 단위는 레이아웃과 캐릭터 비중을 포함한 전체 디자인이다. 특정 요소 하나의 인과 효과를 검증한 실험이라고 주장하지 않는다.

## 디자인 가설

| 항목 | A: 캐릭터 중심 | B: 시작 우선 |
| --- | --- | --- |
| 첫인상 | 나를 바라보는 두 해설자 | 바로 읽고 시작하는 해설 노트 |
| 모바일 우선순위 | 제목 → 캐릭터 → CTA | 제목 → CTA → 두 관점 설명 |
| 캐릭터 역할 | 큰 통합 일러스트 | 작은 화자/역할 표시 |
| 확인할 질문 | 캐릭터가 친근함과 이해를 높이는가? | 빠른 CTA와 역할 설명이 진입을 돕는가? |

실제 실험을 진행하게 되면 첫 홈 노출 대비 소개 진입과 첫 풀이 완료를 함께 확인할 수 있다. 현재는 대표가 직접 비교하는 디자인 프리뷰이며, 트래픽 배정·방문자 추적·실험 지표 수집은 설정하지 않았다.

## 파일과 적용 범위

`a.html`/`a.css`는 이전 디자인의 별도 보관본으로 만들어 기존 파일을 덮어쓰지 않았다. `b.html`/`b.css`는 새 방향이다. 이미지는 기존 `../duo-home-ready/assets/`를 공유하며 추가 AI 이미지를 생성하지 않았다. 두 안의 화면 텍스트·버튼·내비게이션은 이미지와 분리된 실제 HTML/CSS다. 가상 진행 상태로 표현하며 실제 패키지 API를 호출하지 않는다. 링크는 기존 로컬 서비스 `http://localhost:3100` 경로로 연결한다.

실제 서비스 적용·로그인 전 화면 변경·배포·커밋·푸시는 하지 않았다.

- A/B의 제목·설명·주 CTA·진행 단계가 같고, UI상 차이를 인물 비중과 배치 중심으로 비교할 수 있음을 모바일/PC 캡처로 직접 확인했다.
