## 발견 (우선순위순)

### P0 — 정확도

1. **음력 윤달 입력 불가.** 음력 선택 시 윤달 옵션이 없고, `lib/saju/calculator.ts:96`은 `Lunar.fromYmdHms(y, m, d…)`로 평달만 계산한다. 1990년은 윤5월이 있는 해라, 1990 윤5월생은 조용히 평5월로 계산된다(월주가 바뀔 수 있음). 음력 생일 쓰는 40대 이상 사용자에게 치명적이며 "사주 틀렸네"로 바로 이탈한다.
   - 제안: 음력 선택 + 해당 연도에 윤달이 있을 때만 "윤달" 체크 노출, 계산에는 음수 월 전달.

2. **출생 시각 기본값 09:00.** 시계 다이얼을 열고 그냥 '확인'만 누르면 오전 9시로 저장된다. 모르는 사람이 대충 확인하면 시주가 틀린 채 풀이된다.
   - 제안: 기본값 없이 열기(시를 고르기 전엔 확인 비활성), 또는 "새벽/아침/낮/저녁/밤쯤" 같은 대략 선택 + "모름" 동선 강화.

### P1 — 흐름·이탈

3. **재방문자에게 진행 상태가 안 보임.** 정보 입력 + 기질 검사까지 끝낸 사람도 홈은 첫 방문자와 같은 소개 화면이고, 큰 버튼은 다시 소개(`/explore/fusion`) → `/fusion/start` → … 로 3번 돌아간다. 원인: `isBeforeStart()`가 베타 무료에서 step이 `personal`이면 "시작 전"으로 본다(사주 풀이 저장본이 없으면 기질 완료 여부와 무관).
   - 제안: `hasProfile`이거나 `tci.answered > 0`이면 시작 전으로 보지 않고, 홈 버튼을 "이어서 사주 풀이 만들기" 등 journey label로.

4. **첫 진입까지 소개가 3겹.** 랜딩(3단계 설명) → 대시보드(같은 3단계 설명 + 히어로) → 소개 페이지(또 3단계 설명) → 입력. 첫 방문자는 같은 설명을 세 번 읽고 4번 탭해야 생일을 넣는다.
   - 제안: 랜딩 '시작하기' 후 첫 방문자는 대시보드를 건너뛰고 소개로 바로, 또는 대시보드 버튼을 바로 `/fusion/start`로.

5. **랜딩 첫 화면(375×812)에 CTA가 없음.** '시작하기'가 한 화면 넘게 스크롤해야 나온다. 하단 고정 CTA 또는 3단계 리스트 축약 필요.

6. **소개 페이지 예시 풀이가 실제 톤과 다름.** 예시 '사주 풀이'는 존댓말·건조한 문체("~볼 수 있습니다")인데 실제 리포트는 반말 팩폭 톤. 판매 포인트(언니 톤)를 보여주지 못하고 기대와 실물이 어긋난다.

### P2 — 용어·카피

7. 소개·사주 화면에 **조후·격국·억부·세운** 같은 용어가 풀이 없이 나열됨(소개 1단계 설명, "이어서 살펴볼 항목"). 규칙상 괄호 일상어 풀이 필요.
8. 하단 탭 **"용신상담"** — 첫 사용자는 '용신'을 모른다. "고민 상담" 등으로.

10. 최종 통합 화면 "올해·내년 기운과 남은 달 주의(**코드로 계산**)" — 구현 용어 노출. "계산해 둔" 정도로.
11. 기질 검사 완료 버튼이 **"검사 결과 보기"**인데 실제로는 최종 통합 풀이로 간다(기질 단독 결과는 꺼져 있음). "사주+기질 풀이 보러 가기"로.
12. 입력 폼: '이름 또는 별명'은 필수인데 `*` 표시가 없음(생년월일·성별엔 있음). 빈 제출 시 브라우저 기본 툴팁만 뜸. '시각 모름 (연·월·일주만으로 풀이)'의 "일주"도 용어.
13. OpenAI/Gemini 전송 고지가 랜딩·입력·사주·통합 화면에 4번 반복. 고지는 필요하지만 입력 화면 1회 + 생성 버튼 옆 한 줄로 줄이면 덜 무겁다. (풀이 화면의 'AI 비노출' 원칙과도 부딪힘 — 법무 판단 필요)
14. 프로필 등록 전부터 헤더에 "나 ⌄" 인물 선택이 보임.

3. **작은 글씨 남발.** 12px 미만 글자: 사주 화면 10px 34곳·11px대 21곳, 홈 9~11px 23곳. 설명·캡션(일간 설명, 막대 해설 등)이 10px라 모바일에서 거의 안 읽힘. 본문 보조 최소 12px 권장.
