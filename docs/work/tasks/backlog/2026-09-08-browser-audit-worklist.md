이 문서는 **실행할 일을 설명하는 계획서**다. 기능 변경·공개 문구·정책·배포에 대한 일괄 승인서가 아니다. 작업 시작 전에 담당자와 이번에 진행할 번호를 합의한다. 특히 정책 내용, 설문 표현, 신규 AI 생성 동선은 제품 담당자의 확인을 받는다. 승인 대기인 항목은 `대기 사유`를 남기고 다음 독립 작업을 진행해도 된다.

### 알아두면 좋은 용어

- **컴포넌트:** 여러 화면에서 재사용하는 화면 조각. 예: 인물 선택 버튼.
- **API:** 화면이 서버에 데이터를 요청하는 주소. 같은 주소라도 `GET`은 보통 조회, `POST/PATCH/DELETE`는 생성·변경·삭제에 쓰인다. 조회에도 부수 효과가 있는 구현이 있으므로 운영 데이터는 테스트에 사용하지 않는다.
- **상태:** 로딩 중, 데이터 없음, 저장본 있음, 실패처럼 화면이 처한 조건.
- **고정 테스트 데이터(fixture):** 실제 개인정보 대신 테스트에 사용하는 가상의 응답과 리포트.
- **가짜 응답(mock):** 실제 서버·AI를 호출하지 않고 테스트 코드가 정해진 응답을 돌려주는 방식.
- **E2E 테스트:** 브라우저가 버튼을 누르고 화면 이동·결과를 자동으로 확인하는 테스트.
- **회귀 테스트:** 수정한 뒤 예전에 되던 기능이 다시 깨지지 않았는지 확인하는 테스트.

### 이번 작업의 공통 성공 기준

- 확인된 개선 10건을 같은 조건에서 다시 검사했을 때 문제가 재현되지 않는다.
- 저장한 풀이와 액션을 다시 찾을 수 있고, 선택한 인물의 정보가 다른 인물 정보와 섞이지 않는다.
- 기본 자동 테스트에서 실제 AI 생성 비용과 운영 데이터 변경이 발생하지 않는다.

기존 제품 흐름인 **풀이 확인 → 상담 → 액션 저장 → 다시 방문**을 유지한다. 새 결제 시스템, 데이터베이스 개편, 전체 디자인 교체는 이번 범위가 아니다. 기존 유즈케이스 UC-02~UC-07을 보완하는 작업이며, 별도 신규 제품 기능을 만드는 계획은 아니다.

자동 검사 예시의 의미:

```text

```

현재 명령의 차이:

- `npm run typecheck`: 타입 오류 확인.
- `npm run test:unit`: 현재는 `lib/ai/*.test.ts`만 실행한다. 새 리포트 변환 단위 테스트를 추가하면 해당 테스트가 실행되도록 스크립트도 갱신해야 한다.

- `npm run eval:render`: **화면 렌더링 테스트가 아니라 AI 프롬프트 문자열 생성 검사**다. AI 호출은 없지만 `/Users/basil/Projects/sajulife/scripts/eval/out/prompts/` 전체를 지우고 다시 만든다. 보관할 파일이 있으면 먼저 별도로 백업한다. 기질·융합을 함께 검사하려면 `npm run eval:render -- tci fusion`으로 한 번에 실행한다. 종류별로 두 번 실행하면 앞선 출력이 지워진다.
- `npm run test:e2e`: 브라우저 테스트. 기본 주소는 3100이며 필요 시 개발 서버를 시작한다.

**전체 E2E 실행 전 주의:** `E2E_EMAIL`·`E2E_PASSWORD`가 있으면 기존 공유 테스트가 실제 링크를 생성·재발급·폐기한다. 기존 공개 링크가 무효가 될 수 있으므로 운영 계정으로 실행하지 않는다. `E2E_BASE_URL`이 운영 주소를 가리키지 않는지도 확인한다. 비밀 값은 이 문서나 명령 기록에 적지 않는다.
