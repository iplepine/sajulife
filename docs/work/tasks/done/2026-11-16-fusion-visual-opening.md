# 최종 리포트 첫 화면의 시각 요약 제안

- Goal: ../../goals/active/2026-06-consulting-loop-validation.md

- 요청: 대표가 최종 사주+기질 리포트 초반의 긴 글을 줄이고 시각적으로 이해를 도울 방법을 문의했다.

현재 `/fusion` 폴리오는 저장 표제 다음에 펼쳐진 긴 본문을 먼저 보여주고, 명식·검사 응답 시각 자료는 본문 뒤에 둔다. 이를 변경하기 전에 디자인팀 네 독립 시안으로 시각 요약의 방법을 비교한다. 기존 서비스 A/B는 별도 디자인 체계로 유지하며 각 시안에서 두 체계의 표현을 확인한다. 시안 번호 01~04는 서비스 A/B와 별개다.

범위: 독립 HTML 시안·모바일/PC 캡처·설명·검증 기록. 가상의 저장 발췌와 가상 응답 점수임을 표시한다. 다섯 해석 축의 임의 점수, 사주와 검사 일치율, 오행↔검사 인과 연결을 만들지 않는다. 실제 적용 시 저장된 원문/계산 자료에 있는 내용만 시각화하며 없는 해석을 보태지 않는다.

완료 기준: 서로 다른 정보 표현 4종, A/B 표현, 390/1440px와 작은 모바일에서 넘침/동작 확인, 실제 뷰포트 캡처 제공. 실제 앱의 표시 순서·본문 펼침 기본값·프롬프트·저장본·생성/권한·배포는 이번 제안에서 변경하지 않는다. 대표 선택 후 해당 방향의 실제 적용 범위를 확정한다. 현재 진행 중인 기질 탭 변경은 보존한다.

## 실행 결과 — 2026-11-16 KST

디자인팀 네 명이 서로 다른 파일에서 독립 제안했다. 신윤복은 ‘두 관점 한 장’, 김홍도는 ‘반응의 흐름 지도’, 이중섭은 ‘상황으로 읽기’, 신사임당은 ‘두 근거 한눈에’를 제작했다. A/B는 각 시안에서 기존 서비스 디자인으로 전환한다.

- 산출물: [비교 화면](../../../../design-previews/fusion-visual-opening/index.html), [시안별 설명·경계](../../../../design-previews/fusion-visual-opening/README.md), `comparison-a.png`·`comparison-b.png` 및 개별 뷰포트 캡처.
- 실행 검증: 네 파일 × A/B × 320/390/1440px = 24개 레이아웃에서 넘침 0·실행 오류 0·이미지 로딩 확인. 주요 발췌/펼침/장면 선택을 직접 실행했다. 390px 모바일의 고정 메뉴 아래끝은 844px로 실제 뷰포트 하단과 일치한다. `qa.json`에 기록했다.
- 시각 검수: 네 모바일 B, A/B 비교 화면과 모바일/PC 캡처를 확인했다. 전체 페이지 캡처 대신 실제 뷰포트 크기를 사용했다.
- 추천: 04를 기본으로 실제 계산 명식/저장된 7축 응답 → 짧은 통합 해석 → 본문으로 읽는다. 실제 본문에 행동이 있으면 03의 행동 카드 한 장을 결합할 수 있다. 01~03의 해석 도식에는 구분된 발췌 자료가 필요하며, 기존에 없는 요약을 즉석에서 만들어 끼워 넣지 않는다.
- 상태: 시각화 방법 제안 완료, 대표 방향 선택 대기. 실제 앱의 순서/펼침·프롬프트·운영 데이터·저장본은 바꾸지 않았다. 실제 AI·API·운영 저장소 접근·커밋·푸시·배포 없음. 제안용 HTML만 추가해 앱 전체 빌드/회귀 검사는 실행하지 않았다.

후속 승인 (2026-11-16 KST): 대표의 “커밋푸시” 요청에 따라 검증된 기질 탭/A·B 보완과 시각 요약 시안 및 문서를 `origin/main`에 커밋·푸시한다. 시각 요약 4종은 제안으로 보존하며 실제 통합 리포트 개편을 선택한 것으로 해석하지 않는다.
